## ✨ 特别之处

### 🔄 Return All 自动分页

以下接口支持 **Return All**。未勾选时，Limit 是最多返回条数（默认 50），超过一页会继续请求，直到凑够或没有下一页。勾选后按游标取完。列表会拆成多条 n8n item。

| 模块   | 接口名称                           | 翻页游标                                                                 |
| ------ | ---------------------------------- | ------------------------------------------------------------------------ |
| 候选人 | 根据条件查询申请信息               | `next`，只在节点内部使用                                                 |
| 候选人 | 获取候选人信息                     | `next`。未取完时写在最后一条，填回「起始游标」继续                      |
| 候选人 | 获取候选人信息V2接口(不迭代)       | `next`，只在节点内部使用。翻页请求只带 `next`                            |
| 候选人 | 获取全部阶段下的候选人信息(分页)   | `next`。未取完时写在最后一条，填回「起始游标」继续。翻页只带 `next`      |
| 用户   | 获取人事信息V3                     | `nextUserId`。未取完时写在最后一条，填回「起始用户 ID」，排序用从旧到新 |
| 人才库 | 查询人才库下候选人                 | `nextCursor`，只在节点内部使用。也可把游标填到「起始游标」接着查         |

勾选 Return All 后，Options 里可加 **Batching** 控制翻页节奏，默认约 3 次/秒。这些接口只能串行翻页，相邻请求间隔约为 Batch Interval / Batch Size。

### ⏱️ 超时与批次管理

接口的 `Options` 里可以配置：

- **Timeout（超时时间）**：请求超时，单位毫秒。`0` 表示不超时
- **Batching（批次管理）**，两种用法：
  - **自动翻页**：Batch Size、Batch Interval。只在勾选 Return All 后出现，用来放慢翻页
  - **同一批输入并发**：Items per Batch 默认 50，Batch Interval 默认 1000 毫秒。添加后同一批请求同时发出，下一批开始前等待间隔；不添加时仍按输入顺序逐条请求

使用输入并发的操作：根据申请ID批量获取候选人信息、获取简历解析文本、获取候选人附件信息、批量获取候选人标签、查询简历筛选评价表、批量推荐用人部门、查询角色信息、查询人才库列表。

## 凭证类型

凭证名称：**Moka Hr API** (`mokaHrApi`)

| 字段                   | 必填 | 说明                                                                     |
| ---------------------- | ---- | ------------------------------------------------------------------------ |
| 系统版本 (region)      | 是   | 中国版 `https://api.mokahr.com`，国际版 `https://hire-r1-api.mokahr.com` |
| Authorization (apiKey) | 是   | 密钥配置页中 Authorization 的 value，形如 `Basic xxxxx`                  |

## 注意事项

1. 所有请求走 HTTPS。密钥配置页的 value 原样放入请求头，不再 Base64。只复制了后面的密钥段时，节点会补上 `Basic` 前缀。
2. 默认业务成功码是 `200`。获取候选人信息、两个全部阶段接口、查询简历筛选评价表、查询角色信息、查询人才库列表、查询人才库下候选人同时接受 `0` 和 `200`。获取人事信息 V3 的成功码是 `0`。
